# PRD：ff14-key2key 視窗介面版（GUI）

| 項目 | 內容 |
|---|---|
| 狀態 | 草案，待確認 |
| 分支 | `dev` |
| 日期 | 2026-11-06 |
| 範圍 | 新增 WinForms 視窗介面；新增「暫停／繼續擷取」、「離開」、「背景執行」三個功能 |

---

## 1. 背景與目標

目前的 `ff14-key2key.exe` 是主控台程式，所有功能都要輸入數字選單來操作，結束映射要按 `Ctrl+C`。而且彈奏時不能用滑鼠點黑色視窗，因為 QuickEdit 會讓輸出凍結。對一般玩家來說門檻偏高。

### 目標
1. 所有功能都改成**按鈕操作**，不用再輸入指令或按 `Ctrl+C`。
2. 新增三個功能：
   - **暫停／繼續擷取**：一個按鈕切換，暫停時 MIDI 訊號不會送到遊戲，再按一次立刻恢復。
   - **離開**：安全結束程式，保證所有按鍵都放開。
   - **背景執行**：把視窗縮到系統匣（右下角通知區），映射繼續運作。
3. **維持零安裝**：只用 Windows 內建的 .NET Framework 4 和 `csc.exe`，雙擊 `build.bat` 就能編譯。

### 非目標（這次不做）
- 不改變按鍵送出的方式（維持 `PostMessage`），也不改鍵位表。
- 不做自動演奏或播放 MIDI 檔。
- 不做多國語言切換（介面先用正體中文）。

## 2. 技術可行性評估

### 2.1 結論：可行，不需要任何外部 SDK

| 需求 | 評估 |
|---|---|
| 視窗介面 | WinForms（`System.Windows.Forms.dll`、`System.Drawing.dll`）是 .NET Framework 4 內建元件，`csc.exe` 預設就會引用。 |
| 系統匣圖示 | WinForms 內建 `NotifyIcon` 和 `ContextMenuStrip`，可以直接用。 |
| 圖示檔 | 不需要外部 `.ico`：執行時用 `System.Drawing` 畫出來，或使用 `SystemIcons`。 |
| 編譯 | `csc.exe /target:winexe` 產生沒有主控台的視窗程式。 |
| 語言限制 | 一樣只能用 **C# 5**（沒有 `$""`、`?.`、`nameof` 等）。WinForms 不需要 Designer，介面全部用程式碼建立。 |

WPF 也是內建的，但 `csc.exe` 不能編譯 XAML，只能用程式碼拼介面，維護成本比較高，所以**不採用**。

### 2.2 現有程式碼可沿用的程度

`Key2Key.cs` 的核心邏輯和主控台介面已經分開，視窗版可以直接沿用核心：

| 類別 | 用途 | 視窗版 |
|---|---|---|
| `Keymap` | 37 鍵對照表 | 直接沿用 |
| `MidiMessage` | MIDI 訊息解析 | 直接沿用 |
| `Engine` | 按下／放開邏輯，防止卡鍵 | 沿用，**新增暫停功能**（見 4.2） |
| `Config` | `config.txt` 讀寫 | 直接沿用（兩個版本共用同一份設定檔） |
| `Ff14Window`、`Ff14PostSink` | 找遊戲視窗、送按鍵 | 直接沿用 |
| `MidiIn` | winmm MIDI 輸入 | 直接沿用 |
| `NoteCatcher` | 校準用的音符收集 | 直接沿用 |
| `LogQueue` | 跨執行緒訊息佇列 | 沿用，新增一個不寫主控台的取出方法 |
| `NativeConsole`、`Options`、`Program` | 主控台介面 | 視窗版**不使用**，另寫 `GuiProgram` |

### 2.3 程式架構與編譯方式

**建議：保留主控台版，另外新增視窗版 exe，兩者共用核心程式碼。**

```
csharp/
  Key2Key.cs      ← 原本的檔案（核心 + 主控台介面），只做最小幅度修改
  Gui.cs          ← 新增：視窗介面（MainForm、系統匣、各功能流程）
  app.manifest    ← 共用（要求系統管理員權限）
  build.bat       ← 改成一次編譯兩個 exe
```

`build.bat` 會產生兩個 exe：

| 輸出 | 編譯方式 |
|---|---|
| `ff14-key2key.exe`（主控台版，維持不變） | `csc /target:exe Key2Key.cs` |
| `ff14-key2key-gui.exe`（視窗版） | `csc /target:winexe /main:Ff14Key2Key.GuiProgram Key2Key.cs Gui.cs` |

用 `/main:` 指定進入點，就不需要拆分 `Key2Key.cs`。這樣對原檔的修改很少，之後要合併上游（原作者）的更新時比較不容易衝突。

對 `Key2Key.cs` 預計只做這些修改：
1. `Engine` 新增 `SetPaused(bool)` / `IsPaused`（見 4.2）。
2. `LogQueue` 新增 `TryTake()`，讓視窗版可以取出訊息。
3. `Program.Describe()`、`Program.HintText()` 從 `private` 改成 `internal`，讓視窗版共用訊息文字。

### 2.4 主要風險

| 風險 | 影響 | 對策 |
|---|---|---|
| MIDI 回呼在背景執行緒觸發，直接改 UI 會當掉 | 程式崩潰 | 沿用主控台版的作法：回呼只寫入佇列，UI 用 `System.Windows.Forms.Timer`（每 50 ms）取出並更新畫面。 |
| 程式異常結束時按鍵沒放開，遊戲裡會卡音 | 遊戲內持續發聲 | 所有結束路徑都要呼叫 `Engine.Shutdown()`，包括 `FormClosing`、`Application.ThreadException`、`AppDomain.UnhandledException`、`SystemEvents.SessionEnding`。 |
| 暫停瞬間剛好有 MIDI 訊息進來，造成卡鍵 | 暫停後仍有一個音卡住 | 暫停旗標在 `Engine` 的鎖裡檢查，並在同一個鎖裡放開所有按鍵（見 4.2）。 |
| 同時開兩個程式搶同一個 MIDI 裝置 | 第二個開啟失敗 | 用具名 `Mutex` 限制只能執行一個視窗版；重複開啟時把已開的視窗叫到前面。 |
| 程式結束後系統匣殘留圖示 | 外觀問題 | 結束時呼叫 `NotifyIcon.Visible = false` 並 `Dispose()`。 |
| 高 DPI 螢幕字體模糊 | 外觀問題 | 在 manifest 宣告 `dpiAware`，並設定 `AutoScaleMode.Dpi`。 |

## 4. 功能需求

優先級：**P0** = 第一版必須有，**P1** = 第一版盡量有，**P2** = 之後再做。

### 4.1 開始／停止映射（P0）
原本選單的 `1`。

- 按「▶ 開始映射」：
  - 用下拉選單選的裝置開啟 MIDI，開始把琴鍵轉成按鍵。
  - 如果還沒有 `config.txt`，先自動進入校準流程（跟主控台版一樣）。
  - 按鈕變成「■ 停止映射」。
- 按「■ 停止映射」：放開所有按鍵、關閉 MIDI 裝置，回到閒置狀態。
- 映射中每 50 ms 檢查一次 FF14 視窗，連線狀態改變時更新指示燈並寫入記錄。
- 收到超出範圍的音符時，在記錄裡顯示提示，建議重新校準（沿用 `HintText`）。
- MIDI 裝置被拔掉時，自動停止映射，並用訊息框提示使用者。

### 4.2 暫停／繼續擷取（P0，新增）
**一個按鈕，按一次暫停、再按一次繼續。**只有在映射中才能按。

- **暫停時**：
  - 立刻放開目前所有按住的按鍵，避免遊戲卡音。
  - 之後收到的 MIDI 訊號都會被忽略，不會送到遊戲。
  - 按鈕變成「▶ 繼續擷取」，狀態變成「已暫停」（黃色），系統匣圖示也變黃。
- **繼續時**：馬上恢復送出按鍵，不需要重新開啟裝置。
- **暫停時，MIDI 裝置維持開啟**：所以繼續時是瞬間恢復，也不會因為裝置被別的程式搶走而無法繼續。
  如果想讓出裝置給 DAW 等其他程式使用，請改按「停止映射」。

| | 暫停擷取 | 停止映射 |
|---|---|---|
| 按鍵 | 全部放開 | 全部放開 |
| MIDI 裝置 | 維持開啟 | 關閉 |
| 恢復速度 | 立即 | 要重新開啟裝置 |
| 其他程式能否使用鍵盤 | 不能 | 可以 |

**實作方式**：在 `Engine` 新增 `SetPaused(bool paused)`：
```csharp
public void SetPaused(bool value)
{
    lock (sync)
    {
        paused = value;
        if (paused) ReleaseAllLocked();
    }
}
```
`Handle()` 在鎖裡多檢查一個條件：`if (closed || paused) return;`。這樣「放開所有按鍵」和「開始忽略訊號」是在同一個鎖裡完成的，暫停瞬間剛好進來的 Note On 不會漏網造成卡鍵。

- 暫停期間一直按住、繼續後才放開的琴鍵：`Engine` 記錄這個鍵沒有按下，所以那個 Note Off 會被安全忽略，不會送出多餘的放開訊號。
- 暫停期間收到的 All Notes Off（CC 120 / 123）：不需要處理，因為暫停時已經全部放開了。

### 4.3 離開（P0，新增）
- 主視窗右下角的「離開」按鈕，以及系統匣右鍵選單的「離開」，都會執行同一套結束流程：
  1. `Engine.Shutdown()`：放開所有按鍵，並拒絕之後的所有輸入。
  2. 如果正在測試音階，中止測試執行緒。
  3. `MidiIn.Close()`：關閉 MIDI 裝置。
  4. 移除系統匣圖示。
  5. `Application.Exit()`。
- 不跳出「確定要離開嗎？」確認框，因為按鍵都已安全放開，離開沒有副作用。
- **視窗右上角的 ✕**：預設行為和「離開」相同（見第 7 節待確認事項）。

### 4.4 背景執行（P0，新增）
- 按「背景執行」：隱藏主視窗、從工作列移除，只留下系統匣圖示。**映射、暫停狀態都維持不變**。
- 按視窗的最小化按鈕 `─`：一般最小化到工作列（不改變系統預設行為）。
- 叫回視窗：雙擊系統匣圖示，或右鍵選單的「顯示視窗」。
- 補充：本程式**本來就不需要視窗在前景也能送出按鍵**，所以背景執行的目的主要是讓桌面和工作列更整潔。

### 4.5 校準最低音（P0）
原本選單的 `2`。改成一個對話框流程：

1. 跳出對話框：「請按下鍵盤『最左邊（最低音）』的琴鍵」，下方有「取消」按鈕。
2. 收到音符後顯示：「收到：MIDI 48 (C3)，請再按下『最右邊（最高音）』的琴鍵」。
3. 如果兩鍵相差不是 36 個半音，跳出訊息框讓使用者選「仍然儲存」或「重新校準」。
4. 儲存到 `config.txt`，並更新主視窗的「目前設定」。
5. 等待超過 20 秒沒收到訊號時，顯示和主控台版相同的提示文字。

- 正在映射中時，「校準」按鈕不能按，要先停止映射（避免同一個裝置被開兩次）。

### 4.6 測試音階（P0）
原本選單的 `3`。

- 不需要 MIDI 鍵盤。找不到 FF14 視窗時，用訊息框提示「請先開遊戲」。
- 倒數 3 秒後依序按 37 個音，最後按一個 C 大調和弦。
- 測試在背景執行緒執行，畫面不會凍結。按鈕在測試時變成「■ 停止測試」，可以隨時中止。
- 每個音都寫入記錄：「偏移 12　C4　按鍵 Q」。
- 測試結束後，如果有按鍵沒送出去，顯示警告（沿用 `Undelivered` 計數）。

### 4.7 監看 MIDI（P0）
原本選單的 `4`。

- 按鈕切換開始／結束監看。監看中只在記錄區顯示收到的音符，**不送出任何按鍵**（沿用 `Describe` 的文字格式）。
- 監看和映射不能同時進行，因為兩者要開同一個 MIDI 裝置。

### 4.8 MIDI 裝置選擇（P0）
取代原本選單的 `5`，以及主控台版需要手動輸入裝置編號的步驟。

- 下拉選單列出所有 MIDI 輸入裝置，旁邊有「重新整理」按鈕。
- 預設選擇的順序和主控台版的 `SelectDevice` 一樣：`config.txt` 的 `device=` → 只有一個裝置時選它 → 名稱含 `x3` / `midiplus` 的裝置 → 第一個。
- 使用者改選裝置時，把裝置名稱寫回 `config.txt` 的 `device=`，下次開啟時自動選好。
- 找不到任何裝置時，下拉選單顯示「（找不到 MIDI 裝置）」，並停用需要裝置的按鈕。

### 4.9 鍵位對照表（P1）
原本選單的 `6`。開一個子視窗，用表格（`ListView`）列出 37 鍵：偏移、MIDI 編號、音名、簡譜、電腦鍵。

### 4.10 琴鍵視覺化（P1）
主視窗中間畫出 37 鍵的鍵盤圖，收到 Note On 時對應的琴鍵會亮起，Note Off 時熄滅；暫停時整個鍵盤變灰。方便確認校準是否正確。

### 4.11 只能執行一個（P1）
用具名 `Mutex` 檢查。已有一個視窗版在執行時，把它叫到前面，自己直接結束。

### 4.12 全域快捷鍵暫停（P2）
例如 `Ctrl+Alt+P`，在遊戲畫面中也能暫停／繼續，不用切換視窗（使用 `RegisterHotKey`）。
要注意避免和 FF14 的按鍵衝突，而且這個組合鍵本身也會被遊戲收到，所以列為之後再評估。

### 4.13 視窗位置記憶（P2）
記住上次的視窗位置，以及上次是否在背景執行。

## 5. 狀態與按鈕可用性

同一時間只會有一種模式（因為 MIDI 裝置一次只能開一次）。

| 狀態 | 開始/停止映射 | 暫停/繼續 | 校準 | 測試音階 | 監看 | 裝置選單 | 背景執行 | 離開 |
|---|---|---|---|---|---|---|---|---|
| 閒置 | ▶ 開始 | ✗ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| 映射中 | ■ 停止 | ⏸ 暫停 | ✗ | ✗ | ✗ | ✗ | ✓ | ✓ |
| 已暫停 | ■ 停止 | ▶ 繼續 | ✗ | ✗ | ✗ | ✗ | ✓ | ✓ |
| 校準中 | ✗ | ✗ | （對話框） | ✗ | ✗ | ✗ | ✗ | ✓ |
| 測試中 | ✗ | ✗ | ✗ | ■ 停止 | ✗ | ✗ | ✓ | ✓ |
| 監看中 | ✗ | ✗ | ✗ | ✗ | ■ 結束 | ✗ | ✓ | ✓ |

```
           開始映射              暫停
  閒置 ─────────────▶ 映射中 ◀────────▶ 已暫停
   ▲                   │      繼續        │
   │      停止映射     │                  │
   └───────────────────┴──────────────────┘
   │
   ├─▶ 校準中 ─(完成/取消)─▶ 閒置
   ├─▶ 測試中 ─(完成/停止)─▶ 閒置
   └─▶ 監看中 ─(結束)──────▶ 閒置

  任何狀態 ──離開──▶ 放開所有按鍵 → 關閉裝置 → 結束程式
  MIDI 裝置中斷 ──▶ 放開所有按鍵 → 閒置 + 提示訊息
```

## 6. 非功能需求

| 項目 | 要求 |
|---|---|
| 相依性 | 只用 .NET Framework 4 內建元件；不加入任何 NuGet 套件或外部 DLL。 |
| 編譯 | 雙擊 `build.bat` 一次產生兩個 exe；GitHub Actions 的 release 同時發布兩個 exe 和各自的 `.sha256`。 |
| 權限 | 和主控台版相同，透過 `app.manifest` 要求系統管理員權限。 |
| 安全性 | 維持現狀：只送出一般按鍵訊息給 FF14 視窗；不讀寫遊戲記憶體、不注入程序、沒有網路功能。 |
| 延遲 | 按鍵送出路徑和主控台版相同（MIDI 回呼 → `Engine` → `PostMessage`），**UI 更新不能放在這條路徑上**，所以延遲不會增加。 |
| 卡鍵防護 | 停止、暫停、離開、裝置中斷、程式例外、Windows 登出／關機，都必須放開所有按鍵。 |
| 設定相容 | 兩個版本共用同一份 `config.txt`，格式不變，可以互換使用。 |
| 程式碼 | 遵守 `Key2Key.cs` 開頭列出的 C# 5 限制；`Gui.cs` 一樣存成 UTF-8 with BOM。 |
